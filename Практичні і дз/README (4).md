## 📚 1. Теоретичні відомості

### 1.1. Взаємодія з консоллю: клас `Scanner`
У Java для зчитування даних, які користувач вводить у вікні термінала (консолі), найчастіше використовують клас `Scanner` із пакету `java.util`.

#### 1. Створення об'єкта Scanner
Для підключення до стандартного потоку введення (`System.in` — потік клавіатури) необхідно імпортувати клас і створити його екземпляр:
```java
import java.util.Scanner; // Обов'язковий імпорт на початку файлу (перед класом)

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        // ... робота з даними ...
        scanner.close(); // Закриття ресурсу наприкінці роботи
    }
}
```

#### 2. Основні методи зчитування даних
| Метод | Що зчитує | Приклад виклику |
| :--- | :--- | :--- |
| `scanner.nextLine()` | Зчитує **весь рядок** до натискання клавіші Enter (разом із пробілами) | `String name = scanner.nextLine();` |
| `scanner.next()` | Зчитує **одне слово** (до першого роздільника: пробілу, табуляції чи Enter) | `String word = scanner.next();` |
| `scanner.nextInt()` | Зчитує ціле число типу `int` | `int age = scanner.nextInt();` |
| `scanner.nextDouble()` | Зчитує дробове число типу `double` (увага на роздільник: крапка чи кома!) | `double price = scanner.nextDouble();` |
| `scanner.nextBoolean()`| Зчитує логічне значення (`true` або `false`) | `boolean flag = scanner.nextBoolean();` |

> [!NOTE]
> Щоб зчитати окремий символ `char`, прямого методу немає. Використовують комбінацію: `char ch = scanner.next().charAt(0);` (зчитує слово і бере його перший символ з індексом 0).

#### 3. Закриття сканера: `scanner.close()`
Коли програма взаємодіє з зовнішнім світом (консоль, файли, мережа), операційна система виділяє ресурси (дескриптори потоків). Виклик `scanner.close()` сигналізує системі, що ресурси можна звільнити.
> [!WARNING]
> Якщо закрити `scanner`, який читає з `System.in`, повторно відкрити `System.in` у цій же програмі вже не вдасться! Тому `scanner.close()` викликають лише тоді, коли всі операції введення в методі `main` повністю завершено.

#### 4. Підступна пастка Scanner: залишковий символ переведення рядка (`\n`)
Найчастіша помилка початківців виникає при чергуванні числових методів (`nextInt()`, `nextDouble()`) та текстового методу `nextLine()`:
```java
System.out.print("Введіть вік: ");
int age = scanner.nextInt(); // Користувач вводить 18 і тисне Enter

System.out.print("Введіть повне ім'я: ");
String fullName = scanner.nextLine(); // ПРОПУСКАЄТЬСЯ! Зчитує порожній рядок!
```
**Чому це відбувається?**
Коли користувач вводить `18` і натискає `Enter`, у буфер потрапляє: `18\n`. Метод `nextInt()` забирає число `18`, але символ нового рядка `\n` залишається висіти в буфері! Наступний метод `nextLine()` бачить цей `\n`, вважає рядок завершеним і миттєво повертає порожній рядок `""`.

**Як виправити (очищення буфера):**
Після виклику `nextInt()` або `nextDouble()` треба додати «холостий» виклик `scanner.nextLine()`, який «з'їсть» залишковий `\n`:
```java
System.out.print("Введіть вік: ");
int age = scanner.nextInt();
scanner.nextLine(); // Очищуємо залишковий перехід рядка з буфера!

System.out.print("Введіть повне ім'я: ");
String fullName = scanner.nextLine(); // Тепер працює ідеально!
```

### 1.2. Умовні оператори: `if`, `if-else`, `if-else-if ladder` та блокова семантика `{}`

#### 1. Базові форми
- **Одиночний `if`:** виконує блок коду, тільки якщо умова істинна (`true`).
  ```java
  if (temperature < 0) {
      System.out.println("На вулиці мороз!");
  }
  ```
- **Розгалуження `if-else`:** одна гілка для `true`, інша для `false`.
  ```java
  if (score >= 60) {
      System.out.println("Іспит складено!");
  } else {
      System.out.println("Іспит не складено.");
  }
  ```
- **Каскад умов `if-else-if ladder`:** послідовна перевірка взаємовиключних варіантів:
  ```java
  if (score >= 90) {
      System.out.println("Відмінно");
  } else if (score >= 75) {
      System.out.println("Добре");
  } else if (score >= 60) {
      System.out.println("Задовільно");
  } else {
      System.out.println("Незадовільно");
  }
  ```

#### 2. Блокова семантика `{}` та пастка «завислого else» (Dangling Else)
Якщо після `if` або `else` не поставити фігурні дужки `{}`, до умови належатиме **лише одна перша інструкція**:
```java
// НЕБЕЗПЕЧНИЙ КОД:
if (isAuthorized)
    System.out.println("Доступ надано");
    System.out.println("Ласкаво просимо!"); // Цей рядок виконається ЗАВЖДИ, незалежно від умови!
```

Ще підступніша проблема — **Dangling Else**:
```java
if (a > 0)
    if (b > 0)
        System.out.println("a > 0 та b > 0");
else
    System.out.println("Хто викликав цей else?"); // Компілятор прив'яже цей else до найближчого if (b > 0), а не до if (a > 0)!
```

> [!IMPORTANT]
> **Золоте правило Clean Code в Java:** Завжди пишіть фігурні дужки `{}` для блоків `if`, `else if` та `else`, навіть якщо тіло складається лише з однієї інструкції.

#### 3. Область видимості змінних (Variable Scope) усередині блоків `{}`
Змінні, оголошені всередині фігурних дужок `{}`, існують **тільки всередині цих дужок**:
```java
if (condition) {
    int localDiscount = 10;
}
// System.out.println(localDiscount); // ПОМИЛКА КОМПІЛЯЦІЇ! localDiscount тут не існує.
```
Якщо результат потрібен за межами блоку, оголосіть змінну **до** конструкції `if`:
```java
int discount = 0; // Оголосили до умови
if (isPremium) {
    discount = 15;
}
System.out.println("Знижка: " + discount); // Працює коректно!
```

### 1.3. Тернарний оператор (`?:`)
Тернарний оператор — це компактна форма умовного розгалуження, яка на відміну від `if` є **виразом** (expression), тобто завжди обчислюється і **повертає конкретне значення**.

#### Синтаксис:
```java
результат = (умова) ? значенняЯкщоTrue : значенняЯкщоFalse;
```

#### Приклади:
```java
// Знаходження більшого з двох чисел:
int max = (a > b) ? a : b;

// Визначення парності:
String parity = (number % 2 == 0) ? "Парне" : "Непарне";

// Пряме виведення в консоль:
System.out.println("Статус: " + (isOnline ? "В мережі" : "Офлайн"));
```

#### Особливості та обмеження:
1. **Єдиний тип результату:** Обидва вирази (`значенняЯкщоTrue` та `значенняЯкщоFalse`) повинні мати однаковий або сумісний тип даних (наприклад, обидва числа або обидва рядки).
2. **Вкладений тернарний оператор:** Можна ланцюжком перевіряти кілька умов:
   ```java
   String sign = (n > 0) ? "Додатне" : (n < 0) ? "Від'ємне" : "Нуль";
   ```
> [!TIP]
> Не зловживайте глибоко вкладеними тернарними операторами. Якщо рівнів вкладеності більше одного, читабельність різко падає, і краще повернутися до класичного `if-else-if`.

### 1.4. Логічні та порозрядні оператори: «ліниві» обчислення (Short-Circuit)

У Java існують два набори операторів «І» та «АБО»:

| Оператор | Назва | Тип оператора | Поведінка («Лінивий» чи «Жадібний») |
| :---: | :---: | :---: | :--- |
| `&&` | Скорочене логічне І (Short-circuit AND) | Логічний (`boolean`) | **Лінивий:** якщо лівий операнд `false`, правий **не обчислюється взагалі**. |
| `&` | Повне логічне / Порозрядне І | Логічний / Цілочисельний | **Жадібний:** завжди обчислює обидва операнди. Для цілих чисел — побітове І. |
| `\|\|` | Скорочене логічне АБО (Short-circuit OR)| Логічний (`boolean`) | **Лінивий:** якщо лівий операнд `true`, правий **не обчислюється взагалі**. |
| `\|` | Повне логічне / Порозрядне АБО | Логічний / Цілочисельний | **Жадібний:** завжди обчислює обидва операнди. Для цілих чисел — побітове АБО. |
| `!` | Логічне заперечення НЕ (NOT) | Логічний (`boolean`) | Інвертує значення (`!true` $\to$ `false`, `!false` $\to$ `true`). |

#### Чому ліниві (short-circuit) перевірки рятують від аварій програми?

##### 1. Захист від ділення на нуль:
```java
int a = 10;
int b = 0;

// Безпечно завдяки &&:
if (b != 0 && (a / b > 2)) { 
    System.out.println("Умова виконана");
}
// Оскільки b != 0 повертає false, вираз (a / b > 2) навіть НЕ викликається!
// Програма працює далі без жодних помилок.
```
> [!CAUTION]
> Якби тут було одинарне `&`: `if (b != 0 & (a / b > 2))`, Java спробувала б обчислити праву частину `10 / 0`, і програма миттєво аварійно завершилася б з критичною помилкою: `ArithmeticException: / by zero`.

##### 2. Небезпека побічних ефектів при лінивих перевірках:
```java
int count = 0;
boolean condition = false;

if (condition && (++count > 0)) {
    // Якийсь код
}
System.out.println(count); // Виведе 0, а НЕ 1! Інкремент ++count не спрацював, бо умова ліворуч була false!
```

##### 3. Порозрядне використання `&` на цілих числах:
Коли `&` або `|` застосовуються до цілих чисел (`int`, `long`), вони виконують побітові операції над двійковими представленнями:
- `number & 1`: якщо результат `0` — число парне (останній біт 0), якщо `1` — непарне.
- `6 & 3`: у двійковій системі `110 & 011 = 010` (число 2).

### 1.5. Конструкція `switch`: класичний варіант проти Modern Switch Expressions

Оператор `switch` призначений для вибору одного з багатьох варіантів залежно від значення виразу.
Допустимі типи виразу в `switch`: цілі числа (`byte`, `short`, `char`, `int`), їхні класи-обгортки, перечислення (`enum`) та рядки (`String`).

#### 1. Класичний `switch` (з ключовим словом `break`):
```java
int dayNumber = 3;
String dayName;

switch (dayNumber) {
    case 1:
        dayName = "Понеділок";
        break;
    case 2:
        dayName = "Вівторок";
        break;
    case 3:
        dayName = "Середа";
        break;
    default:
        dayName = "Невідомий день";
        break;
}
```

##### Ефект провалювання (Fall-through):
Якщо забути оператор `break`, виконання програми не зупиниться, а "провалиться" в наступний блок `case`, виконуючи його код, навіть якщо умова не збігається!
Іноді це використовують свідомо для об'єднання кейсів:
```java
switch (dayNumber) {
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        System.out.println("Робочий день");
        break;
    case 6:
    case 7:
        System.out.println("Вихідний день");
        break;
    default:
        System.out.println("Некоректний день");
        break;
}
```

#### 2. Modern Switch Expressions (Java 14+)
У сучасній Java з'явився набагато компактніший, безпечніший та виразніший синтаксис:

##### А. Стрілочний синтаксис (`->`):
- Жодного «провалювання» (fall-through)!
- Оператор `break` більше не потрібен!
- Можна вказувати кілька значень через кому в одному `case`:
```java
switch (dayNumber) {
    case 1, 2, 3, 4, 5 -> System.out.println("Робочий день");
    case 6, 7          -> System.out.println("Вихідний день");
    default            -> System.out.println("Помилка");
}
```

##### Б. Switch як вираз із поверненням значення:
`switch` може повертати значення прямо в змінну:
```java
String dayType = switch (dayNumber) {
    case 1, 2, 3, 4, 5 -> "Будній";
    case 6, 7          -> "Вихідний";
    default            -> "Невідомий";
}; // У кінці ставиться крапка з комою, бо це інструкція присвоєння!
```

##### В. Багаторядкові блоки та ключове слово `yield`:
Якщо для обчислення значення всередині стрілки потрібен складний блок коду з фігурними дужками `{}`, для повернення фінального значення використовується слово `yield` (аналог `return`, але тільки для блоку switch):
```java
int day = 5;
String schedule = switch (day) {
    case 1, 2, 3, 4 -> "Звичайний навчальний день";
    case 5 -> {
        System.out.println("П'ятниця: скорочені пари!");
        yield "Короткий день (до 14:00)";
    }
    case 6, 7 -> "Вихідний! Час відпочинку";
    default -> throw new IllegalArgumentException("Некоректний день: " + day);
};
```

> [!IMPORTANT]
> **Вимога повноти (Exhaustiveness):**
> Коли `switch` використовується як вираз для повернення значення у змінну, компілятор вимагає, щоб **були оброблені всі можливі значення**. Тому гілка `default` є обов'язковою (якщо не використовуються перерахування `enum`, що перекривають усі варіанти).

### 1.6. ⭐ Додаткова тема: Порівняння рядків у розгалуженнях (`==` проти `.equals()`) та робота рядків у `switch`

Це одна з найголовніших пасток, з якою зіштовхується кожен, хто починає писати програми з розгалуженнями та введенням даних з консолі.

#### Чому `userInput == "admin"` не працює?
Погляньте на цей код:
```java
Scanner scanner = new Scanner(System.in);
System.out.print("Введіть роль: ");
String role = scanner.nextLine(); // Користувач вводить з клавіатури: admin

if (role == "admin") {
    System.out.println("Ласкаво просимо, Адміністраторе!");
} else {
    System.out.println("Доступ заборонено!"); // НАДРУКУЄТЬСЯ САМЕ ЦЕ!
}
```
**Чому так відбувається?**
1. Для **примітивних типів** (`int`, `double`, `boolean`) оператор `==` порівнює **значення** комірок пам'яті.
2. Для **посилальних типів** (клас `String`, об'єкти) оператор `==` порівнює **адреси в пам'яті** (посилання на об'єкти), а не сам текст!
   - Літерал `"admin"` у коді зберігається в спеціальній області пам'яті — *String Pool*.
   - Рядок, зчитаний через `scanner.nextLine()`, створюється в динамічній пам'яті (*Heap*) як новий окремий об'єкт.
   - Оскільки адреси двох об'єктів різні, `role == "admin"` повертає `false`, навіть якщо їхні літери абсолютно однакові!

#### Правильний спосіб: методи `.equals()` та `.equalsIgnoreCase()`
Для перевірки вмісту рядків за символами завжди використовуйте метод `.equals()`:
```java
// Точний збіг (з урахуванням регістру):
if (role.equals("admin")) { ... }

// Збіг без урахування регістру (підійде "admin", "Admin", "ADMIN"):
if (role.equalsIgnoreCase("admin")) { ... }
```

> [!TIP]
> **Прийом «Йода-умови» (захист від `NullPointerException`):**
> Замість `userInput.equals("exit")` безпечніше писати `"exit".equalsIgnoreCase(userInput)`. Якщо раптом `userInput` виявиться `null`, такий вираз поверне `false` замість падіння програми з помилкою.

#### А чому ж тоді `switch` чудово працює з рядками?
Починаючи з Java 7, конструкція `switch` офіційно підтримує рядки:
```java
String command = scanner.nextLine();

switch (command) {
    case "start" -> System.out.println("Запуск системи...");
    case "stop"  -> System.out.println("Зупинка системи...");
    case "exit"  -> System.out.println("Вихід із програми.");
    default      -> System.out.println("Невідома команда!");
}
```

## 📋 3. Критерії оцінювання та чек-лист для самоперевірки

### Чек-лист для студента:
1. **Код компілюється без помилок:** звертайте увагу на підкреслення в IntelliJ IDEA.
2. **Звільнення ресурсів:** наприкінці методу `main` викликано `scanner.close()`.
3. **Захист від переповнення буфера Scanner:** після викликів `nextInt()` та `nextDouble()` перед наступним `nextLine()` додано очищувальний виклик `scanner.nextLine()`.
4. **Правильне порівняння рядків:** порівняння тексту виконується через `.equals()` або `.equalsIgnoreCase()`, а не через `==`.
5. **Блокова семантика:** блоки `if`, `else if` та `else` завжди взяті у фігурні дужки `{}`.
6. **Ліниві перевірки:** у складених умовах ризиковані операції (наприклад, ділення) розміщені праворуч від оператора `&&` після перевірки дільника на 0.
7. **Форматування та конвенції:**
   - Код відформатовано гарячими клавішами: `Ctrl + Alt + L` (Windows/Linux) або `Cmd + Option + L` (macOS).
   - Назви змінних відповідають стилю **camelCase**.
