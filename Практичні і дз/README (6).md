## 📚 1. Теоретичні відомості

### 1.1. Філософія ООП: Чому процедурного коду стало замало?

До цього моменту всі наші програми були **процедурними**: ми писали окремі змінні та окремі цикли й методи, які їх обробляли. Наприклад, щоб описати трьох студентів, доводилося створювати купу розрізнених змінних:
```java
// Процедурний підхід: дані "розмазані" по пам'яті
String student1Name = "Олександр";
int student1Age = 19;
double student1Gpa = 4.8;

String student2Name = "Марія";
int student2Age = 18;
double student2Gpa = 4.9;
```
Якщо параметрів студента стає 20, а студентів — 500, такий код перетворюється на хаос. Найгірше те, що **дані та дії над ними існують окремо одне від одного**.

> **Об'єктно-орієнтоване програмування (ООП)** — це парадигма програмування, в якій головними будівельними блоками є не окремі функції та змінні, а **об'єкти**, що об'єднують у собі **стан** (дані / поля) та **поведінку** (дії / методи).

У реальному житті нас оточують об'єкти: автомобіль, смартфон, банківський рахунок, персонаж гри. Кожен із них:
1. **Має характеристики (стан / поля):** колір авто, баланс рахунку, рівень здоров'я героя.
2. **Вміє виконувати дії (поведінка / методи):** автомобіль може гальмувати, рахунок — приймати депозит, герой — атакувати.

### 1.2. Клас та Об'єкт: Креслення проти Реального будинку

Головне базове розрізнення в ООП — це різниця між **Класом** та **Об'єктом**:

- **Клас (Class)** — це креслення, шаблон, схема або новий власний тип даних, що описує, які поля та методи матимуть майбутні об'єкти. Клас сам по собі не займає пам'ять під дані екземпляра — це лише інструкція для JVM.
- **Об'єкт (Object / Instance)** — це реальний екземпляр, створений у пам'яті комп'ютера за кресленням класу. За одним кресленням будинку можна побудувати сотні реальних будинків на різних вулицях.

```mermaid
flowchart TD
    Blueprint["КЛАС (Креслення / Шаблон)<br><b>class Car</b><br>• brand<br>• speed<br>• drive()"]
    Blueprint -->|new Car()| Obj1["ОБ'ЄКТ 1 (У пам'яті Heap)<br>brand = 'BMW'<br>speed = 120"]
    Blueprint -->|new Car()| Obj2["ОБ'ЄКТ 2 (У пам'яті Heap)<br>brand = 'Audi'<br>speed = 90"]
    Blueprint -->|new Car()| Obj3["ОБ'ЄКТ 3 (У пам'яті Heap)<br>brand = 'Tesla'<br>speed = 0"]
```

#### Синтаксис опису класу:
```java
// Файл Car.java
package semester1.practice06;

public class Car {
    // 1. Поля класу (стан об'єкта)
    public String brand;
    public int speed;

    // 2. Методи класу (поведінка об'єкта)
    public void drive() {
        System.out.println(brand + " їде зі швидкістю " + speed + " км/год");
    }
}
```

#### Синтаксис створення об'єкта через оператор `new`:
```java
// У класі запуску (наприклад, Practice06.java)
Car myCar = new Car(); // Створення екземпляра класу Car
myCar.brand = "BMW";   // Встановлення значення поля через крапку
myCar.speed = 120;
myCar.drive();         // Виклик методу об'єкта
```

### 1.3. Модель пам'яті: Stack (Стек) та Heap (Купа)

Розуміння того, де саме живуть об'єкти, позбавляє від 90% помилок початківців:

1. **Стек (Stack):** зберігає примітивні локальні змінні методу та **посилання (адреси)** на об'єкти.
2. **Купа (Heap):** динамічна область пам'яті, де створюється сам об'єкт та зберігаються всі його поля.

```mermaid
flowchart LR
    subgraph Stack [Стек викликів (Stack)]
        ref["myCar (посилання)<br>адреса: @2a139a55"]
    end
    subgraph Heap [Купа пам'яті (Heap)]
        subgraph ObjectInstance ["Об'єкт класу Car"]
            f1["brand = 'BMW'"]
            f2["speed = 120"]
        end
    end
    ref --> ObjectInstance
```

#### Важливі наслідки посилальної природи:

##### 1. Копіювання посилань (дві змінні на один об'єкт):
```java
Car carA = new Car();
carA.brand = "Toyota";

Car carB = carA; // carB НЕ копіює сам автомобіль! carB отримує посилання на той самий об'єкт!
carB.brand = "Lexus";

System.out.println(carA.brand); // Надрукує "Lexus"!
```

##### 2. Значення `null` та фатальний виняток `NullPointerException`:
Якщо посилання нікуди не вказує, його значенням є `null`:
```java
Car ghostCar = null;
ghostCar.drive(); // КРИТИЧНА ПОМИЛКА: java.lang.NullPointerException!
// Звернення через крапку до null викликає аварійне падіння програми.
```

### 1.4. Поля класу та значення за замовчуванням (Default Values)

На відміну від локальних змінних усередині методів, які обов'язково треба ініціалізувати перед використанням, **поля класу автоматично отримують дефолтні нульові значення** при створенні об'єкта оператором `new`:

| Тип поля | Значення за замовчуванням |
| :--- | :--- |
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `boolean` | `false` |
| `char` | `'\u0000'` (пустий символ) |
| Посилальні типи (`String`, масиви, інші класи) | `null` |

```java
public class UserProfile {
    public String username; // буде null
    public int age;          // буде 0
    public boolean isActive; // буде false
}
```

### 1.5. Модифікатори доступу (Access Modifiers)

Модифікатори доступу керують тим, з яких саме частин програми можна звертатися до класів, їхніх полів та методів.

У Java існує 4 рівні доступу (від найбільш відкритого до найсуворішого):

| Модифікатор | Усередині того ж класу | Усередині того ж пакету | У класах-нащадках | У будь-якому іншому місці |
| :--- | :---: | :---: | :---: | :---: |
| `public` |  |  |  |  (повний доступ звідусіль) |
| `protected` |  |  |  | ❌ (тільки для спадкування) |
| *(default)* без слова |  |  (package-private) | ❌ | ❌ |
| `private` |  | ❌ (доступ заборонено) | ❌ | ❌ (максимальний захист) |

#### Чому не можна робити всі поля `public`? Принцип інкапсуляції
Уявіть банківський рахунок із публічним полем `balance`:
```java
public class BankAccount {
    public double balance; // ПОГАНО: відкритий прямий доступ
}

// Зловмисник або неуважний програміст у Practice06.java:
BankAccount acc = new BankAccount();
acc.balance = -1_000_000; // Катастрофа! Баланс став від'ємним без перевірок!
```

> [!IMPORTANT]
> **Золоте правило чистого ООП:**
> 1. Поля класу роблять **`private`**, щоб захистити їх від прямого зламу та некоректних даних.
> 2. Доступ до полів надають через **`public` методи** (геттери/сеттери або спеціальні бізнес-методи), які перевіряють коректність операцій.

### 1.6. Анатомія та базове створення методів

> **Метод** — це іменований блок коду всередині класу, який описує дію або поведінку об'єкта.

#### Загальна структура методу:
```java
[модифікатор_доступу] [тип_повернення] назваМетоду([список_параметрів]) {
    // тіло методу (алгоритм дій)
    // [return значення;] // якщо тип_повернення не void
}
```

#### 1. Методи без повернення значень (`void`):
Ключове слово `void` вказує на те, що метод виконує дію (наприклад, друкує щось у консоль або змінює поле об'єкта), але **нічого не повертає** назад у точку виклику:
```java
public class Dog {
    public String name;

    // Метод void без параметрів
    public void bark() {
        System.out.println(name + " каже: Гав-гав!");
    }

    // Метод void з вхідним параметром
    public void sleep(int hours) {
        System.out.println(name + " спить " + hours + " годин.");
    }
}
```

#### 2. Методи з поверненням значення (`return`):
Якщо метод повинен щось обчислити і віддати результат (число, рядок, логічне значення тощо), замість `void` вказують відповідний тип даних. У тілі методу **обов'язково** має бути інструкція `return`:
```java
public class Calculator {
    // Повертає ціле число int
    public int sum(int a, int b) {
        return a + b;
    }

    // Повертає дробове число double
    public double getCircleArea(double radius) {
        return Math.PI * radius * radius;
    }

    // Повертає логічне значення boolean
    public boolean isAdult(int age) {
        return age >= 18;
    }
}
```

Виклик у `Practice06.java`:
```java
Calculator calc = new Calculator();
int result = calc.sum(10, 25); // result отримає значення 35
boolean adult = calc.isAdult(16); // adult отримає false
```

#### 3. Ключове слово `this` та уникнення колізій імен:
Часто параметри методу мають такі самі імена, як і поля класу. Ключове слово `this` означає **«поточний екземпляр об'єкта»**:
```java
public class Person {
    private String name;
    private int age;

    // this.name — це поле об'єкта в Heap
    // name — це локальний параметр методу в Stack
    public void setName(String name) {
        this.name = name;
    }

    public void setAge(int age) {
        if (age >= 0 && age <= 125) { // Валідація даних!
            this.age = age;
        } else {
            System.out.println("Помилка: некоректний вік " + age);
        }
    }

    public int getAge() {
        return this.age;
    }

    public String getName() {
        return this.name;
    }
}
```

### 1.7. Масиви як поля класу

Об'єкт може містити не лише примітивні змінні, а й **масиви** (як одновимірні, так і двовимірні матриці). Методи класу можуть працювати з цими масивами всередині:

```java
public class StudentJournal {
    private String studentName;
    private int[] marks; // Масив оцінок всередині об'єкта!

    public void setMarks(int[] marks) {
        this.marks = marks;
    }

    public double calculateAverage() {
        if (marks == null || marks.length == 0) return 0.0;
        int sum = 0;
        for (int mark : marks) {
            sum += mark;
        }
        return (double) sum / marks.length;
    }
}
```

### 1.9. Q&A (Часті запитання на співбесідах)

#### Q1: У чому принципова різниця між класом та об'єктом?
**Відповідь:** Клас — це опис, креслення, тип даних у коді програми (існує на етапі компіляції). Об'єкт — це фізична область динамічної пам'яті (Heap), створена за цим кресленням під час виконання програми за допомогою `new`.

#### Q2: Чому не можна викликати нестатичний метод без створення об'єкта?
**Відповідь:** Нестатичний метод працює зі станом конкретного об'єкта (його полями через `this`). Якщо об'єкт не створено, в пам'яті немає полів, із якими міг би працювати метод.

#### Q3: Що таке інкапсуляція простими словами?
**Відповідь:** Це об'єднання даних та методів їх обробки в одному класі разом із приховуванням прямого доступу до даних (`private`) та наданням безпечного публічного інтерфейсу (`public` методи) з валідацією.

#### Q4: Що станеться, якщо метод з типом повернення `int` не містить `return`?
**Відповідь:** Код не скомпілюється. Компілятор Java вимагає гарантованого повернення значення відповідного типу на всіх гілках виконання.

   - `public int getAntiDiagonalSum()` — знаходить суму елементів побічної діагоналі ($j == \text{length} - 1 - i$);
   - `public boolean isDiagonalSymmetric()` — перевіряє, чи сума головної діагоналі дорівнює сумі побічної.
3. Протестуйте на матриці $3 \times 3$:
   ```text
   [1, 2, 3]
   [4, 5, 6]
   [7, 8, 9]
   ```
   (Головна: $1+5+9 = 15$; Побічна: $3+5+7 = 15 \to$ симетричні!).
